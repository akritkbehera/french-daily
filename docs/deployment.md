# Deployment

French Daily deploys as a static PWA to **GitHub Pages** from the `main` branch of `akritkbehera/french-daily`, served at:

**https://akritkbehera.github.io/french-daily/**

There is no backend, no API keys, and no server-side anything — GitHub Pages serves pre-rendered static assets only.

## Pipeline

`.github/workflows/deploy.yml` runs on every push to `main`:

1. **Checkout + Node 22** (npm cache enabled).
2. `npm ci`
3. `npm run build:packages` — bundle the MCP server (esbuild → `packages/mcp-server/dist/index.js`).
4. `npm run build:web` — Vite production build of `apps/web` with base path **`/french-daily/`**, including `vite-plugin-pwa` (Workbox precache manifest + service worker).
5. **Upload Pages artifact** (`actions/upload-pages-artifact`, path `apps/web/dist`).
6. **Deploy** (`actions/deploy-pages`) — requires the workflow-level `pages: write` + `id-token: write` permissions and an `environment: github-pages` deployment.

### One-time repository setup

```bash
gh repo create akritkbehera/french-daily --public --source . --push
# In repo Settings → Pages: Source = "GitHub Actions"
```

Subsequent pushes to `main` deploy automatically.

## Base path

The app is configured for the project-pages subpath: Vite `base: '/french-daily/'`, manifest `scope`/`start_url` under `/french-daily/`, and the service worker registered at that scope. Everything (assets, icons, `manifest.webmanifest`, `sw.js`) resolves under the subpath.

There is **no client-side router** — the whole app is one document with state-based view switching — so there are no deep-link 404s to handle on Pages. A `?view=` query parameter is accepted for PWA shortcuts (e.g. "Practice" from the install menu).

## PWA specifics

- **Install**: web app manifest with name/short_name, theme colors, `display: standalone`, maskable + standard icons generated by `scripts/generate-icons.mjs` (sharp, from one SVG source: 192/512 PNG, maskable 512, apple-touch 180, favicon SVG).
- **Offline**: `vite-plugin-pwa` with Workbox `generateSW` precaches the full app shell. After the first visit the app runs with no network. Content and the engine are bundled — nothing is fetched at runtime.
- **Updates**: the service worker updates in the background; the app surfaces a refresh prompt so an old session is never yanked mid-practice.
- **Theme**: light/dark/system via a `dark` class on `<html>` + `theme-color` meta kept in sync.

## Local verification (mirrors CI)

```bash
npm run check          # lint + typecheck + unit tests + production build
npm run build:web
npm run preview        # serves http://localhost:4173/french-daily/
```

The Playwright suite (`npm run test:e2e`) runs exactly against this preview build at the `/french-daily/` base path, so e2e failures catch deployment-path regressions before CI does.

## Post-deploy checklist

- [ ] `https://akritkbehera.github.io/french-daily/` loads (valid TLS, correct base path).
- [ ] All 7 screens navigate; light/dark toggle works.
- [ ] DevTools → Application → Manifest: icons and `start_url` under `/french-daily/`.
- [ ] Service worker registers; reload offline still works.
- [ ] Lighthouse PWA/Performance sanity (target: fast first paint on mobile; bundle is well under 1 MB of JS).

## Operational notes

- **Secrets**: none exist in this repo. Never commit tokens; `gh` auth is local-only.
- **Rollback**: revert the offending commit on `main`; Pages redeploys the previous state. User progress is unaffected (it lives in each user's browser).
- **Cache**: GitHub Pages serves with short cache lifetimes; the PWA's own Workbox cache handles repeat visits.

## Alternative hosting

Because the build is a self-contained static bundle under a base path, it can be dropped on any static host (Netlify, Cloudflare Pages, an S3 bucket). Only two things must match: serve `apps/web/dist` at the configured base (`/french-daily/` or change `base` in `apps/web/vite.config.ts`), and serve `sw.js` from the app root.
